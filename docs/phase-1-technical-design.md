# VeVit Tools – Phase 1 technical design

## Scope

Phase 1 hardens public server endpoints, establishes one canonical tool registry,
generates browser-safe metadata and creates repeatable structural tests. It does
not implement the broad UI redesign, the final search UX or VeVit Account SSO.

## Working baseline

The implementation branch starts at `c0bc3775fc52b773735169ba3c9be26fd4741d98`
(`main`). The original mounted snapshot was incomplete only: it lacked
`assets/js/site.js`, `assets/js/lib/tool-ui.js`,
`assets/js/lib/purify.min.js` and `assets/js/lib/pdf.worker.min.js`. All four
are present in the verified upstream checkout. Their absence would respectively
break header behavior, most tool UI behavior, safe Markdown rendering and PDF.js
worker-backed PDF tools. No replacement assets are invented in this phase.

## Canonical registry

`includes/registry.php` owns every public tool fact. Its public tool schema is:

```php
[
  'slug' => 'pdf-merge',
  'name' => 'Sloučení PDF',
  'description' => 'Sloučí více PDF souborů do jednoho.',
  'category' => 'pdf',
  'processing_location' => 'client',
  'icon' => 'Files',
  'new' => false,
  'keywords' => ['sloučit', 'spojit', 'merge'],
  'status' => 'working',
  'availability' => 'available',
  'requirements' => [
    'browser_features' => ['File API'],
    'local_assets' => ['assets/js/lib/pdf-lib.min.js'],
    'php_extensions' => [],
    'external_services' => [],
    'hosting_constraints' => [],
    'verification' => 'verified'
  ],
  'privacy_note' => 'PDF zůstává ve vašem prohlížeči.',
  'declared_test_target' => 'happy_path',
]
```

`verified_test_level` is deliberately absent from this hand-authored record. It
is generated by the executed test report and cannot claim a result which has
not been observed. Valid target and verified levels are `unverified`,
`structural`, `route_smoke`, `browser_smoke`, and `happy_path`.

Valid `status` values are `working`, `limited`, `experimental`, `coming_soon`,
`unavailable_on_wedos`, and `broken`. Valid `availability` values are
`available`, `requires_external_service`, `requires_browser_support`,
`unavailable_on_wedos`, and `not_implemented`.

The registry validator rejects contradictory pairs: `working/not_implemented`,
`unavailable_on_wedos` with a different availability, `broken/available`, and
a verified level above the recorded level in the report. `coming_soon` may only
use `not_implemented` or `requires_external_service`.

## Export pipeline

```
includes/registry.php
  -> scripts/export-tools.php (validation, public projection, atomic JSON write)
  -> assets/data/tools.json
  -> scripts/generate-index.py
  -> index.html
```

The PHP exporter writes a deterministic, slug-sorted, public-only projection
with `JSON_UNESCAPED_UNICODE | JSON_UNESCAPED_SLASHES | JSON_THROW_ON_ERROR`.
It writes a same-directory temporary file and atomically renames it only after
validation and encoding succeed. It exits non-zero on errors and never exports
server configuration, secrets or private implementation values.

## HTML to PDF security model

User HTML is never inserted into the main document. A pure sanitizer removes
`script`, `iframe`, `object`, `embed`, `base`, `form`, `meta`, `link`, active
SVG content, all `on*` attributes and external resource URLs. Only small,
static document markup is rendered in a sandboxed `srcdoc` iframe without
`allow-scripts`, navigation permissions or automatic `allow-same-origin`.

The iframe contains a restrictive CSP. A browser test determines whether
html2canvas can render that opaque-origin document. If it cannot, the report
documents the limitation before any narrower exception is considered; an
`allow-same-origin` exception is allowed only with the same sanitizer, no
`allow-scripts`, no navigation and a regression test proving active content
does not execute.

## SSL checker security model

Hostname parsing rejects URLs, userinfo, paths, ports and IP literals. A
resolver abstraction returns all A and AAAA results. Every result is rejected
when loopback, private, link-local, unspecified, multicast, reserved,
documentation, benchmark or IPv4-mapped IPv6. A request is rejected if any
usable resolved address is unsafe.

The transport opens `ssl://<approved-ip>:443` directly, avoiding a second DNS
lookup. TLS keeps the original hostname in `peer_name` and SNI with
`verify_peer=true` and `verify_peer_name=true`. No redirects are used. The API
maps outcomes to `verified`, `expires_soon`, `expired`, `hostname_mismatch`,
`untrusted_chain`, `unreachable`, `dns_rejected`, or
`verification_unavailable` without exposing IPs, socket errors or paths.

Resolver, address policy and transport are injectable so tests use fixtures and
never connect to internal networks.

## Rate limiting and AI

AI, feedback and SSL checker are server-cost or abuse-sensitive: unavailable
rate-limit storage produces a controlled `503`, not fail-open. Client-only
tools never depend on it. The Ollama endpoint remains development-only; a
client-supplied model is rejected, and server configuration selects an explicit
allowlisted model. Input limits and a bounded timeout remain server-side.

## Commits and rollback

1. `docs: add phase 1 technical design and implementation plan`
2. `fix: harden HTML to PDF, SSL checks and public endpoints`
3. `feat: add canonical tool registry and generated public dataset`
4. `test: add registry, generator and route smoke foundation`
5. `docs: document truthful tool availability and phase 1 results`

Every generated file is reproducible. Each commit is independently revertible;
the rollback path is reverting the corresponding commit and regenerating
`tools.json` and `index.html` from the restored registry.
